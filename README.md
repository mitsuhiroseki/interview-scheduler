# 面接日程調整アプリ

社内の採用担当者(全員が「採用担当 兼 面接官」を兼務)が、候補者からもらった希望日時(3〜5件)をまとめて入力すると、それぞれの日時ごとに対応できる担当者が分かり、そのまま面接を予約できるWebアプリ。

- 設計ドキュメント: [DESIGN.md](./DESIGN.md)
- 判断メモ(AIとのやり取り・設計変更点): [NOTES.md](./NOTES.md)

## 動作環境

- Ruby 3.4.10
- Rails 8.1.3
- SQLite3(追加のミドルウェアは不要)

## セットアップ手順

```bash
git clone https://github.com/mitsuhiroseki/interview-scheduler.git
cd interview-scheduler
bundle install
bin/rails db:create db:migrate db:seed
bin/rails server
```

起動後、ブラウザで `http://localhost:3000` を開いてください。

## 未実装・簡略化した部分

以下は [DESIGN.md](./DESIGN.md) の「やらないこと」に対応する部分で、今回はスコープ外として実装していません。

- 2次・3次面接の管理(1次面接のみを対象にしています)
- 候補者自身による希望日時の入力
- Googleカレンダー等の外部カレンダー連携
- 稼働時間帯・休憩時間を変更するための管理画面(値自体は `business_hours` テーブルに持たせているので、DBを直接更新すれば変更は可能です)
- 候補者への確定連絡の自動送信(メール・Slack通知等)
- 候補者情報のうち、氏名以外の項目(応募職種・連絡先など)
- 候補者の重複統合(同姓同名の名寄せ、候補者検索)。検索のたびに新しい候補者データを作成しています
- ロール別の権限管理(全員が同一ロールのため)

また、実装を通じて以下は簡略化しています。

- 予約の日程変更は「開始時刻の変更」のみに対応しており、担当者の変更・追加はできません(担当者を変えたい場合はキャンセルして再度アサインする運用を想定)
- 自動テスト(RSpec・Minitestなど)は書いていません。動作確認は開発中に手動(curlおよびブラウザ)で行いました
- ログイン機能は簡易な実装で、パスワードリセットやユーザー招待の仕組みはありません(ユーザーは`db/seeds.rb`のダミーデータのみ)
- 日程検索・比較画面はサーバーサイドのHTMLのみで作っており、JavaScriptによる非同期更新(送信すると画面遷移が発生する形)です
- 入力した候補日時(検索条件)そのものはデータベースに保存していません。確定した面接だけが`interviews`として残ります

## 開発メモ

- `json` gemのバージョンが3.x系だと、Rails 8.1 + Ruby 3.4の組み合わせでセッションCookieの復号時に `ArgumentError` が発生する既知の非互換があったため、Gemfileで `json` を `~> 2.9` に固定しています。
